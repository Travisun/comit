# 通知与激励体系蓝图（Discourse 式）

> 状态：**规划文档**。第一部分（站内通知与徽章/佩戴）已实现；本文件描述邮件分层、摘要与
> 激励机制的完整目标形态与落地路径。全部基于现有架构：notifications 扩展（database/mail
> 双渠道 + notificationPrefs 用户偏好）+ pg-boss 队列（cron 与延迟任务）+ mail-templates
> 模板覆写系统。

---

## 一、现状盘点

### 已有

| 能力 | 现状 |
| --- | --- |
| 站内通知（database 渠道） | ✅ 全事件覆盖：评论/回复/关注/私信/点赞/转发/审核/举报/徽章等 |
| 邮件渠道 | ✅ 即时发送（事件 → mailChannel → 模板 → `mail.send` 队列 → SMTP） |
| 用户偏好矩阵 | ✅ `users.notificationPrefs`（key → 渠道数组），设置页可逐事件开关 database/mail |
| SSE 实时推送 | ✅ 通知创建即 broadcast，顶栏角标实时更新 |
| 模板覆写 | ✅ 后台可改邮件标题/正文（mail-templates 系统） |
| 审核结果通知 | ✅ 拒绝通知（仅自己可见 + 重提指引）；通过不通知 |

### 缺口（本蓝图要解决的）

1. 邮件只有「即时」一档——点赞类高频事件也会逐封发信，骚扰且易进垃圾箱。
2. 没有「离线摘要」——用户三天不回来，错过的回复/关注不会汇总成一封「你错过了什么」。
3. 偏好键名漂移（已于本迭代修正 `NOTIFICATION_EVENTS`），但缺少「层级」概念。
4. 激励动作零散（欢迎/里程碑），缺少统一编排。

## 二、通知分层模型（重要性 → 邮件策略）

| 层级 | 事件 | 邮件策略 | 默认 |
| --- | --- | --- | --- |
| **P0 即时**（社交强信号） | 回复我、私信、关注我、审核未通过、徽章授予、举报处理结果 | **立即发**（现状） | 开 |
| **P1 当日摘要** | 内容被点赞/转发/收藏/标记解决方案、帖子被审核通过 | 合并到**每日一封**「今日动态」（当日 20:00 本地时区），面板默认关、摘要默认开 | 摘要 |
| **P2 离线摘要** | 错过的热门内容、关注的作者新发文、社区公告 | 仅当用户 **≥3 天未登录**时触发，每 7 天至多一封「你错过了什么」 | 开（3 天阈值） |
| **P3 事务性** | 邮箱验证、密码重置、2FA 变更、数据导出完成 | **立即发**，不受偏好与摘要控制 | 恒开 |

实现要点：

1. **分级注册**：notifications 扩展的 `deliver()` 增加第三参 `importance: "immediate" | "daily" | "digest"`；
   `daily/digest` 层级不入 mailChannel，改为写 `email_digest_queue` 表（扩展自有表：
   userId / notificationId / importance / created_at）。
2. **摘要任务**：cron `ext.<id>.daily-digest`（每日 20:00）+ `ext.<id>.weekly-digest`（周一 09:00）
   → 聚合队列表中未发送行 → 按用户渲染一封摘要邮件（模板：今日获得的赞/回复/关注 + 热帖链接）
   → 发送后标记已发。用户「最后活跃时间」（`users.lastLoginAt` 已有）≥3 天才发 weekly。
3. **本地时区**：v1 用固定站点时区（`APP_URL` 受众以 zh 为主，20:00 CST 可接受）；v2 再存用户 UTC 偏移。
4. **偏好 UI**：设置 → 通知 矩阵每行增加第三列「邮件策略」（即时/每日摘要/仅站内），
   写入 notificationPrefs 同键的第三渠道 `"digest"`。

## 三、激励与促活策略（Discourse 对标）

Discourse 的核心机制与我们的映射：

| Discourse 机制 | 我们的落地 |
| --- | --- |
| Welcome Post（注册后系统欢迎帖） | `user:registered` → 运营号在用户主页留言欢迎（人工/半自动），+ P0 站内欢迎通知（已有注册邮件） |
| 发文鼓励（First link 提示、编辑宽限期） | 发布成功 toast 增加分享链接复制；30 分钟内「编辑不重审」已是现状 |
| Like/Reply 即时提醒 | 已有（P0 层级） |
| 每日/每周摘要 | 第二节 P1/P2 |
| Badges（一次性成就） | 徽章扩展（已实现）——后台颁发为主，自动策略见下 |
| Leaderboard（榜单） | 热门页已有获赞/浏览数据源；后续可加「周度创作者」榜单挂件 |

### 激励事件 → 通知文案基调（全部鼓励式、不施压）

| 触发点 | 时机 | 通知 |
| --- | --- | --- |
| 注册欢迎 | 注册验证通过 | 站内 + 邮件：欢迎语 + 「先完善资料/发第一条动态」引导 |
| 首篇内容发布 | 第一条内容过审 | 站内：「你的第一篇内容已发布 🎉 继续保持」 |
| 首次被关注 | 第一次被关注 | 站内（follow.created 已覆盖，无需额外） |
| 内容被点赞 ≥10 | 跨越阈值（一次性） | 站内：「你的内容获得了 10 个赞」 |
| 内容被转发 ≥5 | 跨越阈值（一次性） | 站内：「你的内容被转发 5 次」 |
| 连续创作 | 每周 ≥2 篇（连续 4 周） | 站内：「坚持创作一个月了」 |
| 徽章授予 | 后台颁发 | 站内（已实现 badge.granted） |

**反骚扰红线**：同一事件类型对同一用户只发一次（阈值类用 notificationPrefs 已有渠道 +
`meta.once` 标记）；所有鼓励类通知默认仅站内、不入邮件。

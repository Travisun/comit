# 运营后台使用指南（Admin Guide）

> 适用范围：用户管理、举报处理操作台、媒体管理、审计日志、邀请码总览。
> 权限模型见 [docs/roles-permissions.md](./roles-permissions.md)。

## 1. 信息架构总览

后台入口统一在 `/admin`（左侧导航，移动端为顶部横滑栏）。各面板职责与所需权限：

| 面板 | 路由 | 职责 | 权限 |
| --- | --- | --- | --- |
| 仪表盘 | `/admin` | 全站运营数据总览 | admin + editor |
| 文章管理 | `/admin/articles` | 内容审核、驳回、删除 | admin + editor |
| 内容审核 | `/admin/moderation` | 关键词 / LLM 审核配置与队列 | admin + editor |
| 评论管理 | `/admin/comments` | 评论隐藏与删除 | admin + editor |
| **举报处理** | `/admin/reports` | 举报队列与一站式处置 | admin + editor |
| 认证审核 | `/admin/verification` | 创作者/组织认证申请 | admin + editor |
| **用户管理** | `/admin/users` | 警告、限时/永久封禁、角色管理 | 仅 admin |
| **媒体管理** | `/admin/media` | 全站图片资产、空间统计、删除 | 仅 admin |
| **审计日志** | `/admin/audit` | 全部敏感操作的只读流水 | 仅 admin |
| **邀请码** | `/admin/invites` | 邀请码总览与作废 | 仅 admin |
| 站点设置 | `/admin/settings` | 平台参数 | 仅 admin |

## 2. 用户处置分级策略

处置手段按烈度递进，建议逐级使用、留有余地：

| 手段 | 入口 | 影响 | 适用场景 |
| --- | --- | --- | --- |
| **警告** | 用户行操作 → 「警告…」 | 仅发送站内通知（+邮件），不改变账号状态 | 首次轻微违规：引战、刷屏倾向、营销内容 |
| **限时封禁** | 「限时封禁…」（1/3/7/30/90 天） | 立即踢下线，封禁期内无法登录，到期自动恢复 | 屡教不改、短期违规（人身攻击、垃圾信息） |
| **永久封禁** | 「永久封禁…」（需输入「永久」确认） | 立即踢下线，永久无法登录，内容保留 | 严重违规：违法内容、大规模 spam、恶意攻击 |
| **解封** | 「解封」或「一键恢复已到期」 | 恢复 `active`，清除封禁字段 | 误判申诉、处分期满 |

运营建议：

1. **先警告后封禁**：警告是低成本预警，也留住了「我们提醒过你」的处置依据（警告内容写入审计）。
2. **限时封禁优先于永久**：给误判留退路；7 天是处理社区冲突的常用档位，spam 倾向用 30 天。
3. **永久封禁必须填写具体原因**：原因会通知到用户并进入审计日志，是申诉处理的唯一依据。
4. **角色管理**（设为管理员/编辑/普通用户）与处置同在下拉菜单中；不能修改自己的角色/状态。

### 状态徽章说明（用户列表）

- `正常`：active。
- `限时封禁 · 剩 X 天`：suspended 且 `bannedUntil` 在未来。悬停显示解封时间与原因。
- `永久封禁`：suspended 且 `bannedUntil` 为空（红色徽章）。
- `已到期待解封`：suspended 但 `bannedUntil` 已过期，等待自动解封；可用页头「一键恢复已到期」批量立即恢复。

## 3. 封禁技术原理（会话门控 + 自动解封，无需定时器）

- 用户表新增 `banned_until timestamptz` 与 `ban_reason text`。
- **会话门控**：`getAuth()`（src/lib/auth/session.ts）在每次请求解析会话时附加条件
  `banned_until IS NULL OR banned_until < now()`，且 `status = 'active'`。
  因此封禁中的用户即使持有未过期 Cookie，下一个请求也会被视为未登录——**踢下线无需等待**。
  封禁操作还会物理删除该用户全部 `sessions` 行，保证凭据彻底失效。
- **自动解封**：`banned_until` 是纯时间比较，不依赖任何定时任务。
  封禁到期的用户在**下一次登录**时，登录接口发现 `bannedUntil` 已过期，会把账号恢复为
  `active` 并清空封禁字段，然后正常放行（登录提示「按到期自动解封」）。
  在此之前，用户列表会将其显示为「已到期待解封」，管理员也可用「一键恢复已到期」手工批量恢复。
- **登录提示**：封禁中登录返回 403：
  - 限时封禁：`账号已被封禁至 {本地化时间}：{原因}`；
  - 永久封禁：`账号已被永久封禁：{原因}`。

## 4. 举报处置 SOP（举报处理操作台）

入口：`/admin/reports`。左侧为举报队列（支持 状态：待处理/已处理/已驳回/全部 × 类型：文章/评论/用户 筛选），点击任意一条，右侧（移动端为弹窗）显示详情面板：

1. **读详情**：举报人卡片、举报理由、被举报对象**内联预览**——
   文章：标题 + 状态 + 正文前 500 字（纯文本）+ 作者；
   评论：内容摘要 + 所属文章链接；用户：用户卡（头像/发帖数/注册时间/当前状态）。
2. **选择处置**（均可先填写「处置备注」，将写入审计日志 `mod_logs.note`）：
   - **忽略**：举报标记 `dismissed`。用于无实质问题的举报。
   - **处理完成**：标记 `resolved`。用于已线下沟通、内容自行修改等场景。
   - **删除内容**：文章→置为 `rejected`（作者可见原因，软处置）；评论→软删除（`status='deleted'`）。举报连带标记 `resolved`。
   - **封禁作者**：弹出与用户管理一致的封禁表单（限时 1/3/7/30/90 天 或 永久，需填写原因）。系统自动定位被举报内容的作者（用户类型举报则是被举报人本人），举报连带 `resolved`。
   - **警告作者**：弹出警告消息表单，向作者发送 `system.warn` 通知，举报连带 `resolved`。
3. **复核**：处置后可在「已处理/已驳回」筛选下回看历史；所有动作在审计日志可查（`report.*`）。

## 5. 媒体管理（/admin/media）

- 统计卡：文件总数 / 总占用空间 / 本月新增。
- 网格缩略图：悬停显示文件名、大小、尺寸、归属用户与上传时间；角标为用途（正文配图/头像/封面/精选）。
- 筛选：按用途（kind）与文件名/用户名搜索；分页浏览。
- 点击放大：大图 + 详情 + **复制链接**（`/api/media/file/{path}`）+ **删除**。
- 删除 = 数据库行 + 磁盘文件（`storage/media/...`）一并移除，并写审计 `media.delete`。
  ⚠️ 删除后引用该图的文章/头像将出现裂图，请先确认引用情况。

## 6. 审计日志（/admin/audit）

- 只读流水，按时间倒序，支持按动作类型筛选（常用动作分组 + 数据中动态出现的动作）。
- 每行：时间 / 操作人（头像+用户名）/ 动作徽章（按前缀着色：`user.*`、`report.*`、`media.*`、`invite.*`）/ 对象（post→`/p/{id}`、user→`/u/{username}` 可点击）/ 备注。
- 对象 ID 点击可跳转前台对应页面，方便对照现场。

## 7. 邀请码总览（/admin/invites）

- 统计卡：总量 / 未使用 / 已使用。
- 表格：邀请码（点击复制）/ 邀请人 / 状态 / 使用者与使用时间 / 创建时间。
- **作废**：仅未使用的邀请码可作废（删除行，写审计 `invite.revoke`）；已使用的是历史记录，不可删除。

## 8. 权限矩阵

各面板与 API 的角色要求见 [docs/roles-permissions.md](./roles-permissions.md)。要点：
用户管理 / 媒体 / 审计 / 邀请码为 **仅管理员**；举报处理台为 **管理员 + 编辑**（编辑可执行全部处置，含封禁作者）。

## 9. 审计合规说明

所有敏感操作都会写入 `mod_logs`（动作、操作人、对象、备注、时间），包括但不限于：

| 动作 | 触发 |
| --- | --- |
| `user.warn` | 发送警告 |
| `user.ban_timed` / `user.ban_permanent` | 限时 / 永久封禁 |
| `user.unban` | 解封（含一键恢复） |
| `user.role` / `user.status` | 角色 / 状态变更 |
| `report.resolve` / `report.dismiss` | 举报处理 / 忽略 |
| `report.delete_content` / `report.ban_author` / `report.warn_author` | 举报台快捷处置 |
| `media.delete` | 删除媒体 |
| `invite.revoke` | 作废邀请码 |

同时，封禁/解封/警告会发出领域事件（`user:banned` / `user:unbanned` / `user:warned`）并给用户发送操作通知（`system.ban` / `system.unban` / `system.warn`），通知失败不影响处置本身。合规要求：处置备注写清依据；永久封禁必须填写原因。
